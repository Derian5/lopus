# Гайд по игровому контенту

Этот документ описывает, как без изменения боевой логики настраивать и добавлять героев, солдатские профессии, врагов, боссов, способности, статусы, предметы, столкновения и контент рынка.

## 1. Где находится контент

| Назначение | Путь |
|---|---|
| Игровые ресурсы | `res://content/demo/` |
| Описания типов ресурсов | `res://content/definitions/` |
| Способности | `res://content/demo/abilities/` |
| Статусы | `res://content/demo/statuses/` |
| Предметы | `res://content/demo/items/` |
| Столкновения | `res://content/demo/encounters/` |
| Враги и боссы | `res://content/demo/` и `res://content/demo/enemies/` |
| Длина маршрута и волна Boss | `res://content/demo/routes/demo_route.tres` |
| Стартовый состав и инвентарь | `res://data/runtime/demo_run_factory.gd` |
| Генерация рынка | `res://data/runtime/market_generator.gd` |
| Покупка, продажа и reroll | `res://data/runtime/market_service.gd` |

`ContentRegistry` при запуске рекурсивно загружает все файлы `.tres` из `res://content/demo/`. Ручная регистрация нового ресурса обычно не нужна.

Ресурс будет зарегистрирован, если:

- он сохранён внутри `res://content/demo/`;
- он наследует `ContentDefinition`;
- поле `id` заполнено;
- его `id` уникален во всём проекте;
- ресурс не содержит `Node` или `NodePath`.

## 2. Рекомендуемый рабочий процесс

Самый безопасный способ создать контент:

1. Найти наиболее похожий существующий `.tres`.
2. В панели FileSystem Godot нажать правой кнопкой и выбрать `Duplicate`.
3. Переместить копию в подходящий каталог внутри `res://content/demo/`.
4. Открыть копию в Inspector.
5. Сразу заменить `id`, `display_name` и `description`.
6. Настроить игровые поля.
7. Запустить игру и тесты из раздела 13.

Дублирование предпочтительнее создания пустого ресурса: оно сохраняет правильные типы вложенных ресурсов и массивов. `.tres` являются текстовыми файлами, поэтому их можно редактировать вручную, но Godot Inspector безопаснее для ссылок на другие ресурсы.

### Общие поля любого контента

| Поле | Назначение |
|---|---|
| `id` | Постоянный технический идентификатор |
| `display_name` | Имя в интерфейсе |
| `description` | Описание и подсказка |
| `icon` | Иконка, если интерфейс её использует |
| `tags` | Метки для логики и классификации |

Рекомендуемые префиксы ID:

| Тип | Формат | Пример |
|---|---|---|
| Герой | `hero.*` | `hero.test_vanguard` |
| Профессия | `job.*` | `job.warrior` |
| Враг или босс | `enemy.*` | `enemy.iron_warden` |
| Столкновение | `encounter.*` | `encounter.warden_guard` |
| Способность | `ability.*` | `ability.greed_dagger_nova` |
| Статус | `status.*` | `status.burn` |
| Предмет героя | `item.*` | `item.bone_bell` |
| Предмет солдата | `item.soldier.*` | В текущем prototype отсутствует |
| Эффект | `effect.*` | `effect.fire_bolt_damage` |

Не меняйте `id` уже выпущенного контента без необходимости. Сохранения хранят ID, поэтому переименование или удаление ID может сделать старое сохранение невалидным. Имя файла и `display_name` менять безопаснее.

## 3. Характеристики юнитов

`StatBlock` содержит:

| Поле | Значение |
|---|---|
| `max_hp` | Максимальное здоровье |
| `damage` | Урон базовой атаки |
| `attack_speed` | Число базовых атак в секунду |
| `movement_speed` | Скорость перемещения |
| `attack_range` | Дистанция базовой атаки |
| `armor` | Броня |

Урон эффектов способности не масштабируется автоматически от `damage`. Например, `DamageEffect.amount = 20` всегда создаёт 20 сырого урона до обработки бронёй независимо от `damage` владельца.

### Герой или враг

У героя и врага `base_stats` являются полными базовыми характеристиками. Если требуется 300 HP и 25 урона, укажите непосредственно `max_hp = 300` и `damage = 25`.

### Солдатская профессия

У профессии `stat_modifiers` являются прибавками к базовому ополченцу, а не итоговыми характеристиками.

База любого солдата до профессии:

| Характеристика | База |
|---|---:|
| HP | 105 |
| Damage | 10 |
| Attack Speed | 1.0 |
| Movement Speed | 108 |
| Attack Range | 46 |
| Armor | 2 |

Например, профессия с `max_hp = 80`, `damage = 2`, `armor = 12` получит 185 HP, 12 damage и 14 armor до veterancy и предметов.

Критически важно: новый `StatBlock` имеет ненулевые значения по умолчанию. Не создавайте для профессии пустой `StatBlock`, иначе она случайно получит +100 HP, +10 damage, +1 attack speed, +100 movement speed и +48 range. Дублируйте подходящий ресурс из `res://content/demo/jobs/` и явно оставляйте ненужные прибавки равными нулю.

### Итоговый порядок расчёта

Герой:

1. `HeroDefinition.base_stats`.
2. Независимый рост каждой характеристики за уровень из `progression/demo_progression.tres`.
3. Модификаторы экипировки.

Солдат:

1. База ополченца.
2. `JobDefinition.stat_modifiers`.
3. Независимый рост каждой характеристики за veterancy.
4. Модификаторы экипировки.

Для предметов все операции `ADD` применяются раньше всех `MULTIPLY`, независимо от порядка в массиве.

## 4. Герои

Тип ресурса: `HeroDefinition`.

Примеры:

- `res://content/demo/heroes/Greed.tres`;
- `res://content/demo/heroes/Envy.tres`;
- `res://content/demo/heroes/Pride.tres`.

Поля героя:

| Поле | Назначение |
|---|---|
| `base_stats` | Полные базовые характеристики |
| `placeholder_color` | Цвет юнита на поле |
| `portrait` | Необязательная текстура портрета для карточки выбора; при отсутствии используется цветной placeholder с инициалами |
| `available_in_new_game` | Включает героя в carousel перед созданием нового забега |
| `selection_order` | Авторский порядок карточки в carousel |
| `tags` | В том числе определяет дальний тип героя |

Чтобы добавить героя:

1. Дублируйте ближайший по роли ресурс героя.
2. Назначьте новый уникальный `hero.*` ID.
3. Настройте полный `base_stats`.
4. Добавьте точный тег `ranged`, если герой должен использовать дальний тип базовой атаки.
5. Включите `available_in_new_game`, если герой должен участвовать в стартовом выборе.
6. Задайте уникальный `selection_order` и при наличии назначьте `portrait`.

`NEW GAME` открывает data-driven carousel всех зарегистрированных героев с `available_in_new_game = true`. Игрок выбирает ровно трёх; порядок нажатий `SELECT` становится порядком HeroState в roster и сохраняется в первом autosave. `DemoRunFactory.HERO_IDS` остаётся только default-составом для автономных тестов и технических preview, а не определяет реальный выбор игрока.

Текущий demo pool содержит семь героев. Greed, Wrath и Pride имеют собственные наборы способностей; остальные четыре героя пока не имеют новых способностей. Чтобы геймдизайнер подключил будущую способность к одному из них, достаточно добавить его `hero.*` ID в `AbilityDefinition.allowed_hero_ids`, включить `available_to_heroes` и заполнить четыре `hero_levels`.

Новый герой начинает забег без способностей. Каждый полученный Hero Level создаёт отдельный обязательный выбор способности именно для повысившего уровень героя. В одном бою несколько героев могут получить по одному или несколько уровней, поэтому после Encounter последовательно открывается несколько выборов; без повышения уровня награды способности нет. Каждый выбор содержит максимум две совместимые с героем способности. Новая способность сразу занимает свободный слот, а повтор уже известной способности повышает её уровень.

Ограничения runtime:

- у героя максимум 4 экипированные способности;
- у героя максимум 6 предметов;
- отдельной настраиваемой очереди способностей нет; AI проверяет экипированные способности в стабильном порядке `ability_ids`.

### Уровни героев

Параметры уровней находятся в `res://content/demo/progression/demo_progression.tres`:

| Поле | Что регулирует |
|---|---|
| `hero_level_xp_thresholds` | Суммарный Hero XP, необходимый для каждого уровня |
| `hero_max_hp_growth_per_level` | Процентный прирост max HP за уровень |
| `hero_damage_growth_per_level` | Процентный прирост damage за уровень |
| `hero_attack_speed_growth_per_level` | Процентный прирост attack speed за уровень |
| `hero_movement_speed_growth_per_level` | Процентный прирост movement speed за уровень |
| `hero_attack_range_growth_per_level` | Процентный прирост attack range за уровень |
| `hero_armor_growth_per_level` | Процентный прирост armor за уровень |

Hero Level начинается с `1`, поэтому Level 1 использует характеристики из `HeroDefinition.base_stats` без бонуса. Для каждой характеристики множитель рассчитывается независимо:

```text
gained_levels = max(Hero Level - 1, 0)
stat_multiplier = 1.0 + gained_levels * stat_growth_per_level
```

Текущие пороги равны `[0, 10, 25, 50, 250]`, а все шесть growth-полей равны `0.5`. Поэтому Level 2 получает +50%, Level 3 +100%, Level 4 +150%, Level 5 +200% к каждой характеристике. Growth применяется к базовым характеристикам героя до модификаторов предметов. Поля можно настраивать независимо, например оставить рост HP и armor высоким, не ускоряя одновременно damage и attack speed.

## 5. Солдаты и профессии

Отдельного `SoldierDefinition` нет. Каждый солдат является runtime-экземпляром, а его характеристики и способности определяются профессией `JobDefinition`.

Имя солдата отображается в формате `Job + Name`, например `Priest David`. Личное имя один раз детерминированно выбирается из общего списка еврейских и старославянских имён в `res://data/runtime/soldier_name_generator.gd`, сохраняется в `SoldierState` и не меняется при смене профессии. Для изменения пула редактируйте только массив `SoldierNameGenerator.NAMES`.

Примеры:

- `res://content/demo/jobs/militia_job.tres`;
- `res://content/demo/jobs/warrior_job.tres`;
- `res://content/demo/jobs/archer_job.tres`;
- `res://content/demo/jobs/priest_job.tres`;
- `res://content/demo/jobs/summoner_job.tres`.

Поля профессии:

| Поле | Назначение |
|---|---|
| `stat_modifiers` | Прибавки к базе ополченца |
| `attack_type` | `melee` или `ranged` |
| `innate_ability_ids` | Врождённые способности каждого солдата профессии; не требуют покупки и не занимают слоты сборки |
| `available_ability_ids` | Все покупаемые уровни способностей профессии; улучшение ссылается на предыдущий уровень через `AbilityDefinition.upgrades_ability_id` |
| `capacity_price` | Цена ещё одного места профессии |
| `unlock_price` | Цена открытия профессии |
| `placeholder_color` | Цвет солдат этой профессии |

Чтобы добавить профессию:

1. Дублируйте наиболее похожую существующую профессию.
2. Назначьте новый `job.*` ID.
3. Настройте только прибавки `stat_modifiers`.
4. Выберите `attack_type`: `melee` или `ranged`.
5. Заполните `innate_ability_ids` и покупаемые `available_ability_ids`; задайте цену каждого уровня и ссылку улучшения на предыдущий уровень.
6. Настройте `unlock_price` и `capacity_price`.
7. При необходимости добавьте предметы с ограничением на новый job ID.

Новая профессия автоматически становится кандидатом рынка на открытие. Исключение: точный ID `job.militia` никогда не предлагается рынком.

`job.summoner` использует `ability.summoner_job_summon` как врождённую active ability. Она всегда добавляется каждому Summoner и проверяется AI раньше покупаемых способностей. Её нельзя убрать или заменить через Job build.

`job.priest` аналогично всегда получает `ability.priest_heal`. Её лечение, cooldown, радиус поиска и дистанция применения редактируются в `res://content/demo/abilities/jobs/priest/priest_heal.tres`.

### Покупаемые способности профессии

Количество назначенных солдат больше не открывает способности. Покупки хранятся в общем `JobBuildState`: способность применяется ко всем текущим и будущим солдатам профессии через её active/passive слоты. Врождённые способности задаются отдельно в `innate_ability_ids`.

Каждый уровень — отдельный `AbilityDefinition` со своей `price`. У I уровня `upgrades_ability_id` пуст; у II он равен ID первого уровня. Оба ID включаются в `JobDefinition.available_ability_ids`. В магазине сначала доступен только I уровень, после покупки — следующий. Улучшение заменяет предыдущий уровень в том же слоте; эффекты уровней не складываются. История покупок сохраняется в `owned_ability_ids`, а устаревший уровень нельзя снова купить или экипировать. Текущие цены в `.tres`: 150 Gold за I и 250 за II.

Fire Arrow I/II у Archer используют прежние постоянные ID `ability.archer_professionalism_fire_arrow_tier_1/2`. Слово `professionalism` в старых ID и именах файлов сохранено для совместимости контента, а самой механики и её порогов больше нет. Формат сохранения `JobBuildState` не изменён: покупки и выбранный уровень уже представлены ID способностей.

Shieldbearer покупает Spiked Shields I/II: `AttackReflectEffect` отражает атакующему 30% или 60% фактически снятого обычной атакой HP. Урон способностей не отражается, а отражённый урон не запускает новое отражение.

Priest покупает `Cleansing Flame I/II`: выбирает союзника, которого сейчас выбрало целью наибольшее число живых врагов, даёт ему `+40/+80` armor и иммунитет к новым `NEGATIVE`-статусам на `4/6` секунд. Cooldown равен `6/4` секунды. Иммунитет не снимает уже действующие статусы и не блокирует урон, knockback, taunt или другие bespoke-механики.

Summoner покупает `Convergence I/II`. После начального 20-секундного cooldown способность сливает всех живых призывов владельца в `Summoned Amalgam` на 10 секунд. Max HP, damage и armor суммируются с множителем `100%/200%`; movement speed и attack range берутся у обычного призыва, а attack speed получает `+20%` базового значения за каждое поглощённое существо. Во время слияния новый призыв заблокирован. При распаде исходные существа получают оставшуюся долю HP объединённого; смерть объединённого существа убивает всю поглощённую группу.

Для способности с `activation_mode = REPLACE_BASIC_ATTACK` AI не выполняет отдельный cast. Когда cooldown готов, она заменяет следующую обычную атаку, сохраняя выбранную базовую цель, attack range, windup и recovery; пока cooldown идёт, обычные атаки продолжаются. Для `PROJECTILE` с `area_radius > 0` все эффекты применяются в момент попадания ко всем врагам в указанном радиусе от точки удара. Радиус включает граничную дистанцию.

Поля `attack_definition_id`, `ai_behavior` и `restriction_tags` сейчас преимущественно описательные. Новое значение в этих полях само по себе не создаёт новый тип атаки или AI.

Чтобы вручную изменить стартовых солдат, редактируйте `DemoRunFactory.create_starting_run()`:

- цикл `for index in 9` задаёт стартовое количество;
- `generated_name` задаёт имя;
- `current_job_id` можно назначить каждому создаваемому `SoldierState`;
- `run.unlocked_job_ids` задаёт открытые профессии;
- `run.job_capacities` задаёт стартовую вместимость профессий;
- `_job_build(...)` задаёт стартовые active/passive способности профессии.

### Veterancy солдат

Все доступные геймдизайнеру параметры veterancy находятся в `res://content/demo/progression/demo_progression.tres`:

| Поле | Что регулирует |
|---|---|
| `veterancy_xp_thresholds` | Суммарный XP, необходимый для каждого Veterancy Level |
| `veterancy_max_hp_growth_per_level` | Процентный прирост max HP за каждый уровень veterancy |
| `veterancy_damage_growth_per_level` | Процентный прирост damage за каждый уровень veterancy |
| `veterancy_attack_speed_growth_per_level` | Процентный прирост attack speed за каждый уровень veterancy |
| `veterancy_movement_speed_growth_per_level` | Процентный прирост movement speed за каждый уровень veterancy |
| `veterancy_attack_range_growth_per_level` | Процентный прирост attack range за каждый уровень veterancy |
| `veterancy_armor_growth_per_level` | Процентный прирост armor за каждый уровень veterancy |
| `damage_xp_rate` | XP за единицу нанесённого damage |
| `healing_xp_rate` | XP за единицу effective healing |
| `tanking_xp_rate` | XP за единицу damage tanked |
| `xp_rounding_mode` | Округление каждой категории: `FLOOR`, `ROUND` или `CEIL` |
| `max_contribution_xp` | Максимум XP за бой; `0` отключает ограничение |

#### Сколько XP получает солдат за бой

Фиксированного XP за участие, победу или выживание нет. Награда зависит от личного вклада:

```text
damage_xp  = round_mode(damage_dealt      * damage_xp_rate)
healing_xp = round_mode(effective_healing * healing_xp_rate)
tanking_xp = round_mode(damage_tanked     * tanking_xp_rate)

battle_xp = damage_xp + healing_xp + tanking_xp
```

Округление применяется к каждой категории отдельно, а не к итоговой сумме. При текущих коэффициентах `0.2` и режиме `FLOOR`:

| Вклад за бой | Расчёт | Полученный XP |
|---|---|---:|
| 120 damage | `floor(120 * 0.2)` | 24 |
| 80 tanking | `floor(80 * 0.2)` | 16 |
| 120 damage + 40 healing + 80 tanking | `24 + 8 + 16` | 48 |
| 9 damage + 9 healing + 9 tanking | `1 + 1 + 1` | 3 |

`effective_healing` не включает лишнее лечение поверх максимального HP. `max_contribution_xp` применяется после сложения трёх категорий.

XP начисляется и уровень пересчитывается после завершения боя. Только выживший Soldier сохраняет XP. Для погибшего Post Battle показывает `potential_xp`, но сам солдат удаляется; его replacement начинает с `0 XP`, Veterancy Level `0`, профессии Militia и пустой экипировки. Смена профессии также полностью сбрасывает накопленный XP и уровень. На поражении выжившие успевают получить XP, но текущий run после этого завершается.

Коэффициенты contribution сейчас общие для Hero XP и Soldier Veterancy XP. Изменение `damage_xp_rate`, `healing_xp_rate`, `tanking_xp_rate`, округления или cap одновременно влияет на обе системы. Если героям и солдатам нужны разные коэффициенты, это уже изменение кода, а не только ресурса.

#### Сколько XP нужно для следующего уровня

Текущий массив: `[0, 10, 25, 50, 100]`. Это накопительные пороги, а не стоимость отдельного уровня:

| Veterancy Level | Суммарный XP | XP от предыдущего уровня | До следующего уровня |
|---:|---:|---:|---:|
| 0 | 0-9 | старт | 10 |
| 1 | 10-24 | 10 | 15 |
| 2 | 25-49 | 15 | 25 |
| 3 | 50-99 | 25 | 50 |
| 4 | 100+ | 50 | максимальный уровень |

Первое значение массива должно оставаться `0`, остальные значения должны строго возрастать. Максимальный Veterancy Level равен `количество порогов - 1`. XP после последнего порога продолжает накапливаться, но новых уровней не даёт.

Чтобы изменить только скорость получения уровней, редактируйте пороги, а не contribution rates. Например, уменьшение порога Level 2 с `25` до `20` ускорит его получение, не меняя сравнительную награду damage, healing и tanking.

#### Какие бонусы даёт veterancy

Каждая характеристика имеет собственный growth за уровень. Итоговый множитель одной характеристики:

```text
stat_multiplier = 1.0 + Veterancy Level * stat_growth_per_level
```

Каждый множитель применяется независимо после сложения базы Militia и модификаторов профессии, но до предметов. Настраиваются:

- max HP;
- damage;
- attack speed;
- movement speed;
- attack range;
- armor.

Сейчас все шесть growth-полей равны `0.5`, поэтому текущие множители совпадают:

| Veterancy Level | Множитель | Бонус каждой характеристики |
|---:|---:|---:|
| 0 | `1.00` | 0% |
| 1 | `1.50` | +50% |
| 2 | `2.00` | +100% |
| 3 | `2.50` | +150% |
| 4 | `3.00` | +200% |

Пример для Warrior без предметов:

| Level | HP | Damage | Attack Speed | Movement | Range | Armor |
|---:|---:|---:|---:|---:|---:|---:|
| 0 | 185.00 | 12.00 | 1.00 | 108.00 | 46.00 | 14.00 |
| 1 | 277.50 | 18.00 | 1.50 | 162.00 | 69.00 | 21.00 |
| 2 | 370.00 | 24.00 | 2.00 | 216.00 | 92.00 | 28.00 |
| 3 | 462.50 | 30.00 | 2.50 | 270.00 | 115.00 | 35.00 |
| 4 | 555.00 | 36.00 | 3.00 | 324.00 | 138.00 | 42.00 |

Важно: одновременный рост нескольких характеристик сильнее одного бонуса того же размера. При текущем `+200%` к damage и attack speed сырой DPS Level 4 равен `3.0 * 3.0 = 9.0`, то есть растёт на 800%. HP и armor также усиливают выживаемость одновременно, а movement и range повышают фактическую эффективность позиционирования. Независимые поля позволяют ослабить такие сочетания без изменения остальных характеристик.

#### Как балансировать veterancy

1. Сначала определите желаемое число пережитых боёв до каждого уровня. Для короткого demo разумнее мыслить не абстрактным XP, а формулировкой вроде «средний выживший получает Level 1 после 2-3 боёв».
2. Соберите из Post Battle вклад солдат разных ролей: damage для Archer, tanking для Warrior, effective healing для Priest. Смотрите медиану, а не лучший результат одного юнита.
3. Если все роли растут слишком быстро или медленно, меняйте `veterancy_xp_thresholds`.
4. Если конкретная роль систематически отстаёт, сначала меняйте соответствующий XP rate. Помните, что это также изменит Hero XP.
5. Если один особенно успешный бой перескакивает несколько уровней, задайте `max_contribution_xp` или увеличьте расстояния между поздними порогами.
6. Если ветераны слишком сильны, уменьшайте growth-поля проблемных характеристик. Пороги регулируют скорость получения силы, а шесть growth-полей независимо регулируют её состав и размер.
7. Проверяйте стоимость адаптации: смена Job обнуляет veterancy. Игрок должен чувствовать потерю, но не отказываться от перестройки армии перед опасным Encounter.
8. Проверяйте permanent death отдельно. Высокий growth делает гибель ветерана очень болезненной и усиливает snowball между удачным и неудачным run.

Для каждой итерации фиксируйте хотя бы четыре значения: средний XP за бой по каждой профессии, бой получения каждого уровня, долю ветеранов, доживающих до Boss, и разницу времени победы между Level 0 и максимальным уровнем. После изменения прогрессии запускайте `tests/test_combat_results.gd`, `tests/test_stage6_builds.gd` и реальный полный маршрут.

## 6. Враги и боссы

### Обычный враг

Тип ресурса: `EnemyDefinition`.

Примеры:

- `res://content/demo/enemies/ogre_brute.tres`;
- `res://content/demo/enemies/troll_spear_thrower.tres`;
- `res://content/demo/enemies/troll_hexer.tres`.

Поля:

| Поле | Назначение |
|---|---|
| `base_stats` | Полные базовые характеристики |
| `attack_type` | `melee` или `ranged` |
| `ability_ids` | Способности в порядке проверки AI |
| `placeholder_color` | Цвет врага |

Чтобы добавить врага:

1. Дублируйте существующего врага.
2. Назначьте новый `enemy.*` ID.
3. Настройте полный `base_stats`.
4. Выберите `attack_type`.
5. Добавьте существующие способности в `ability_ids`.
6. Добавьте ID врага в `enemy_ids` хотя бы одного encounter.

Новый враг автоматически зарегистрируется, но не появится в забеге без ссылки из столкновения.

### Босс

Тип ресурса: `BossDefinition`, наследует все поля врага.

Пример: `res://content/demo/enemies/iron_warden.tres`.

Дополнительные поля:

| Поле | Назначение |
|---|---|
| `phase_count` | Количество фаз |
| `phase_health_thresholds` | Доли HP для перехода на следующие фазы |
| `phase_damage_multiplier` | Множитель damage на каждой новой фазе |
| `phase_attack_speed_multiplier` | Множитель attack speed на каждой новой фазе |
| `telegraph_color` | Цвет предупреждения |
| `phase_telegraph_text` | Текст предупреждения |

Для `N` фаз нужно ровно `N - 1` порогов. Пороги задаются от большего к меньшему и находятся строго между 0 и 1. Например, три фазы могут иметь `[0.66, 0.33]`. Фазовые множители не могут быть меньше `1.0`.

## 7. Столкновения

Тип ресурса: `EncounterDefinition`.

Ресурсы разложены по актам: `res://content/demo/encounters/act_1/`, `act_2/` и пока пустой `act_3/`.

Длина маршрута настраивается отдельно в `res://content/demo/routes/demo_route.tres`:

| Поле | Назначение |
|---|---|
| `act_one_boss_wave` | Номер боя Act I с боссом; начинается с `1` |
| `act_two_battle_count` | Общее количество боёв Act II |
| `act_one_enemy_power_curve` | Сила врагов Act I по индексу боя (см. «Сложность Act I») |

Сейчас `act_one_boss_wave = 13` и `act_two_battle_count = 12`: Act I содержит двенадцать обычных боёв и босса 13-м боем, Act II — двенадцать боёв. Изменение `act_one_boss_wave` одновременно меняет длину Act I: победа над боссом переводит run в Execution, после которого начинается Act II.

| Поле | Назначение |
|---|---|
| `enemy_ids` | Точный состав врагов |
| `gold_reward` | Награда за победу |
| `act` | Акт 1 или 2 |
| `min_encounter_index` | Первый индекс боя, где карта доступна |
| `max_encounter_index` | Последний индекс боя, где карта доступна |
| `difficulty_hint` | `Low`, `Moderate`, `High`, `Elite` или `Boss`; влияет и на частоту появления карты |
| `enemy_power` | Относительная сила врагов этой карты |
| `key_properties` | Свойства состава, видимые игроку |
| `is_unknown` | Скрывает состав карты |
| `is_boss` | Помечает боссовую карту |

Повтор одного ID в `enemy_ids` создаёт несколько экземпляров врага. Например, три одинаковых ID создадут трёх одинаковых врагов.

### Столкновения с подкреплением

Подкрепления настраиваются прямо в любом `EncounterDefinition`, включая boss-карты. Рабочие примеры находятся в `res://content/demo/encounters/act_1/encirclement.tres` и `ogre_summon.tres`.

| Поле | Назначение |
|---|---|
| `enemy_ids` | Враги, которые находятся на поле в начале боя |
| `reinforcement_enemy_ids` | Враги, появляющиеся как подкрепление |
| `reinforcement_alive_threshold` | Подкрепление приходит, когда живых врагов остаётся не больше указанного числа; допустимы `0`, `1`, `2` |
| `reinforcement_entry_direction` | `ALL_SIDES` распределяет новых врагов по четырём краям арены, `RIGHT_SIDE` размещает всю группу у правого края |

Подкрепление приходит только один раз. Порог `0` означает, что сначала должна погибнуть вся стартовая группа, но бой не завершится: новые враги появятся до проверки победы. Для порогов `1` и `2` подкрепление вступает в бой одновременно с оставшимися врагами. Когда подкрепления включены, стартовая группа должна содержать больше врагов, чем указанный порог.

Чтобы включить механику у существующей обычной или boss-карты, заполните `reinforcement_enemy_ids`. Пустой массив полностью отключает подкрепления; значения порога и направления в этом случае не используются. Создавать другой тип ресурса или менять код не нужно.

У стартовых врагов runtime ID имеют вид `enemy-00`, а у подкрепления `enemy-reinforcement-00`, поэтому обе группы отдельно отображаются в боевой статистике. Карта Encounter показывает стартовый состав, состав подкрепления, порог и направление входа. Для unknown-карты оба состава скрываются.

В `EncounterDefinition` индексы начинаются с нуля, хотя `act_one_boss_wave` использует понятный дизайнеру номер с единицы:

| Часть маршрута | Индексы |
|---|---|
| Act I | `0..act_one_boss_wave - 1` |
| Boss Act I | `act_one_boss_wave - 1` |
| Act II | `0..act_two_battle_count - 1` |

Например, `act_one_boss_wave = 7` создаёт шесть обычных боёв с индексами `0..5` и Boss с индексом `6`. Boss-карты автоматически появляются только на настроенной boss-волне: их собственные `min_encounter_index` и `max_encounter_index` не управляют положением босса. Для каждого добавленного обычного индекса всё равно нужно расширить диапазоны существующих encounter-карт или создать минимум две новые известные карты.

Ограничения маршрута:

- на каждом слое требуется минимум две известные карты;
- на одном слое допускается максимум одна unknown-карта;
- unknown-карта должна давать больше золота, чем любая известная карта слоя;
- настроенная boss-волна Act I содержит только boss-карты;
- boss-карты запрещены на остальных слоях;
- известная карта должна иметь хотя бы одно `key_properties`;
- boss-карта должна иметь `difficulty_hint = "Boss"`;
- unknown-карта не может быть boss-картой.

Первый бой нового run является фиксированным tutorial: `encounter.tutorial_volley` выбирается автоматически, после чего сразу открывается Management. Поэтому `act_one_boss_wave` должен быть не меньше `2`. После каждого обычного боя отдельный экран сначала предлагает ровно две карты следующего Encounter; выбранная карта открывает Management, где последовательно обрабатываются накопленные при повышении уровней Hero ability choices. После Boss сначала выполняется обязательный Execution, затем выбирается первый Encounter Act II; награды казнённого героя пропускаются.

В Management выбор Encounter не дублируется: выбранный бой кратко показан в header. Экран всегда состоит из армии по профессиям слева, контекстного инспектора по центру и Market с inventory справа. Способности и предметы в инспекторе показаны квадратными icon slots: до появления авторской текстуры используется цветная заглушка с инициалами. Hero и Soldier всегда показывают минимум четыре ability slots; только Hero дополнительно показывает шесть item slots. Soldier можно перетащить на заголовок профессии, Market Job ability на конкретный слот общей Job-сборки, а inventory или Market item на equipment slot выбранного Hero. Hero abilities в Market не появляются. Job unlock и capacity по двойному клику применяются без экипировки. Двойной клик по предмету общего Inventory автоматически занимает первый свободный слот выбранного Hero, а при полном наборе заменяет выбранный equipment slot. Чтобы снять предмет, перетащите занятый equipment slot на заголовок общего Inventory.

У каждого Hero и Soldier в инспекторе есть две независимые настройки Combat Behavior. `NEAREST ENEMY` выбирает ближайшего доступного врага. `FARTHEST ENEMY` в начале боя заставляет идти к самому дальнему врагу на поле; после первой выполненной базовой атаки юнит до конца этого боя переключается на ближайшие цели. Сохранённый выбор не меняется, поэтому следующий бой снова начинается с дальней цели. `AVOID DAMAGE` сохраняет стандартный кайтинг дальнего юнита; при отключении дальник не отступает во время attack recovery. Для ближнего юнита avoidance запускает настроенный по времени отход после каждого полученного ближнего удара. Если базовая атака готова, перед отходом юнит один раз отвечает атакующему; новый ближний удар перезапускает таймер отхода. Настройки сохраняются отдельно для каждого юнита. По умолчанию все выбирают ближайшего врага, дальники избегают урон, а ближники нет.

При начальной автоматической расстановке впереди стоят melee-солдаты, за ними melee-герои, затем ranged-юниты. Шаг строк и колонн — до 96 px; на небольшой арене расстояния сокращаются до доступного пространства. Превью и бой используют `FormationService`; ручные позиции имеют приоритет. Движение, отбрасывания, телепортации, призывы и подкрепления не перестраивают сохранённую формацию.

### Спокойное движение и дистанции

Боец сохраняет доступную базовую цель, пока другая не станет заметно ближе: выигрыш больше `max(32 px, 20% текущей дистанции)`. Принудительные цели и охота на заднюю линию сохраняют приоритет.

Личное пространство отделено от коллизии: радиусы мягкого расхождения — 44 px у обычного бойца, 52 у героя, 24 у призыва и 56 у босса. Оно влияет на руление при движении, а не постоянно толкает атакующих на месте. Физическое устранение настоящих пересечений остаётся отдельным механизмом.

Ближники резервируют 12 точек в двух боковых секторах цели: по 6 слева и справа, в пределах ±20° от горизонтали. Резервирование учитывает тесноту соседних точек и распределяет бойцов между флангами; точки остаются в пределах реальной дальности атаки. Начало базового/заменяющего удара разрешено только сбоку (`abs(dy) <= 0.6 * abs(dx)`), включая контратаки и frenzy. Root не разрешает удар сверху/снизу; дальние атаки свободны от этого ограничения. Уже начатый замах попадает независимо от последующего смещения цели. Боец закрепляет точку подхода, старается войти на 14 px внутрь дальности, останавливается с допуском 8 px и обходит центр врага по дуге; может остановиться раньше, если уже сбоку и минимум на 4 px внутри дальности. Небольшое смещение цели не перестраивает подход, пока точка остаётся боковой. Руление обновляет выбранное направление с интервалом 0.18 s, кроме значительных изменений ситуации.

Базовый удар (включая `REPLACE_BASIC_ATTACK`) после начала windup фиксирует цель. Её отход за дальность, новый taunt, решение об отступлении или готовый призыв не отменяют и не перенаправляют начатый удар. Дальность проверяется при выборе момента начала атаки. Если цель к моменту удара погибла, замах завершается без переноса на другую цель. Смерть атакующего прекращает действие; stun по-прежнему приостанавливает действия. Для стандартных способностей сохраняются их собственные правила cast range.

На время замаха боец останавливается; анимация укладывается в определённый симуляцией интервал `ATTACK_SWING_FRACTION` (по умолчанию 2/3 цикла атаки). До его завершения добровольное движение и новые действия отложены. После него движение во время recovery использует ходьбу, а не боевую позу. Готовый дальник в радиусе выстрела начинает атаку сразу, не дожидаясь навигационной точки.

Дальник начинает отход при дистанции меньше 55% своего attack range и заканчивает после увеличения дистанции до 80% либо достижения выбранной точки. После melee-попадания учитывается также reach преследователя с запасом; цель отхода ограничена собственной дальностью стрельбы. Точка фиксируется, небольшие колебания не меняют план. Во время отбега юнит показывает ходьбу и смотрит по движению; после безопасного отхода останавливается, поворачивается к цели и стреляет, когда готова атака. Начатый выстрел заканчивается до отхода. У края арены или при отсутствии прогресса 0.6 s невозможный отход прекращается и не блокирует стрельбу. Root запрещает движение, но не выстрел по доступной цели. Короткий ответный отход melee-бойца с AVOID DAMAGE сохраняется отдельно.

Параметры движения находятся в `Combatant`/`CombatSession`, интервалы расстановки — в `FormationService`. Все новые решения и таймеры обновляются шагами симуляции, а не кадрами отрисовки; распределение точек не расходует боевой RNG. Регрессии: `tests/test_combat_movement.gd`, `tests/test_committed_attacks.gd`.

### Сложность Act I

Сложность Act I задаётся тремя слоями. Первые два перемножаются в общую силу `p`, которая даёт врагу `p^0.85` Max HP и `p^1.15` Damage: урон растёт быстрее здоровья, чтобы поздние бои становились опаснее, а не длиннее (по таймауту в 120 секунд побеждает сторона с большим суммарным HP). Это касается стартовой группы и подкреплений; призванные существа используют свои базовые значения.

| Слой | Где | Назначение |
|---|---|---|
| `act_one_enemy_power_curve` | `demo_route.tres` | Сила врагов по индексу боя (`0..12`). Растёт вместе с уровнями героев и veterancy солдат |
| `enemy_power` | `EncounterDefinition` | Относительная сила конкретной карты внутри своего tier |
| `base_stats` | `EnemyDefinition` | Базовые характеристики врага |

Пример: Ogre Brute (950 HP, 19 Damage) в карте с `enemy_power = 1.1` на 9-м бою (`curve[8] = 3.35`): `p = 3.685`, HP `950 × 3.685^0.85 ≈ 2880`, Damage `19 × 3.685^1.15 ≈ 85`.

`difficulty_hint` теперь принимает `Low`, `Moderate`, `High`, `Elite` или `Boss`. Он управляет не только иконками угрозы на карте, но и частотой появления: `EncounterDefinition.selection_weight()` даёт лёгким картам больший вес в начале акта, а `High` и `Elite` — ближе к боссу. Диапазон `min_encounter_index..max_encounter_index` по-прежнему жёстко ограничивает, где карта может появиться.

Сейчас Act I содержит 12 обычных боёв (индексы `0..11`) и босса 13-м боем (`act_one_boss_wave = 13`).

### Генератор контента и симулятор баланса

Враги, вражеские способности и все карты Act I генерируются скриптом `tools/balance/gen_act1_content.py` — все числа собраны в его таблицах `T` (способности), `S` (характеристики) и `ENC` (карты). После правки таблиц запустите `python3 tools/balance/gen_act1_content.py .` из корня проекта. Можно править и `.tres` напрямую в редакторе, но следующий запуск генератора перезапишет эти файлы.

`tools/balance/balance_sim.gd` проигрывает карты против синтетических армий нужной стадии забега (уровень героев, veterancy, профессии). Пример:

```
godot --headless --fixed-fps 60 --path . --script res://tools/balance/balance_sim.gd -- auto bog_king_court,war_drums 0 7 idx=mid
```

Аргументы: стадия (`auto` выбирает её по индексу боя), список карт или `all`, номер тройки героев, seed, затем необязательные `idx=min|mid|max|N`, `power=X`, `rp=X`, `abilities`. Каждая строка `SIM {...}` содержит победу, длительность, погибших солдат (`sd`) и героев (`hd`).

### Визуальная реакция на урон и лечение

Общие параметры мигания и отталкивания всех боевых юнитов настраиваются в сцене `res://combat/combatant.tscn`:

1. Откройте `res://combat/combatant.tscn` в Godot.
2. Выберите корневой узел `Combatant` типа `CharacterBody2D`.
3. В Inspector найдите экспортированные поля скрипта `Combatant`.
4. Измените нужные значения и сохраните сцену.

| Поле Inspector | Значение по умолчанию | Назначение |
|---|---:|---|
| `damage_flash_color` | Белый `#FFFFFFFF` | Цвет полной заливки юнита при получении урона |
| `damage_flash_duration` | `0.1` секунды | Длительность мигания при уроне |
| `damage_knockback_distance` | `10` | Отталкивание от удара, равного `damage_knockback_reference_percent` от Max HP цели |
| `damage_knockback_reference_percent` | `5` | Доля Max HP (в процентах), которой соответствует `damage_knockback_distance` |
| `damage_knockback_max_distance` | `36` | Максимальное отталкивание от одного удара |
| `healing_flash_color` | Жёлтый `#FFE633FF` | Цвет полной заливки юнита при фактическом лечении |
| `healing_flash_duration` | `0.1` секунды | Длительность мигания при лечении |

Эти значения глобальны для Hero, Soldier, Summon, Enemy и Boss, потому что все боевые юниты создаются из одной сцены `combatant.tscn`. Это не поля ресурсов конкретного героя или врага.

Белая реакция на урон срабатывает, если после брони положительный урон снял HP или был полностью/частично поглощён щитом. Промах и нулевой урон реакцию не запускают. Отталкивание идёт по направлению от позиции источника к цели и ограничивается границами арены. Дистанция пропорциональна доле Max HP, которую снял удар (включая поглощённое щитом): удар на 5% HP отталкивает на 10, на 1% — на 2, на 20% и больше — на максимальные 36. Отталкивание меньше 0.5 не применяется, поэтому мелкий урон по тяжёлым целям их почти не сдвигает. Специальное отталкивание способности складывается с этим общим отталкиванием.

Жёлтая реакция срабатывает только при фактически восстановленном HP. Попытка лечения юнита с полным здоровьем не запускает мигание и никогда не отталкивает цель.

## 8. Способности

Тип ресурса: `AbilityDefinition`.

Способности хранятся по типу и конкретному владельцу:

- Hero: `res://content/demo/abilities/heroes/<hero>/`;
- Job: `res://content/demo/abilities/jobs/<job>/`;
- Enemy: `res://content/demo/abilities/enemies/<enemy>/`.

Одна способность принадлежит одному Hero, Job или Enemy. Не создавайте универсальные Hero abilities и не назначайте один ability ID нескольким типам владельцев.

### Основные поля

| Поле | Назначение |
|---|---|
| `kind` | `ACTIVE` или `PASSIVE` |
| `activation_mode` | `STANDARD` для обычного AI-cast или `REPLACE_BASIC_ATTACK` для замены следующей готовой базовой атаки |
| `cooldown_seconds` | Перезарядка активной способности |
| `initial_cooldown_seconds` | Стартовая перезарядка при начале боя; `0` означает готовность сразу |
| `targeting_policy` | Правило выбора цели |
| `excluded_target_status_id` | Status ID, который исключает цель для `RANDOM_ENEMY_WITHOUT_STATUS` |
| `delivery_method` | Способ доставки |
| `effects` | Эффекты в порядке исполнения |
| `area_radius` | Радиус AoE; у `PROJECTILE` это область вокруг точки попадания |
| `target_search_radius` | Максимальный радиус поиска цели; `0` означает без ограничения |
| `cast_range` | Дистанция применения; если цель дальше, владелец сначала идёт к ней; `0` означает применение без проверки дистанции |
| `required_recent_damage_seconds` | Способность доступна только если владелец получил HP-урон или урон в щит не более указанного числа секунд назад; `0` отключает условие |
| `presentation_color` | Цвет снаряда или телеграфа |
| `presentation_text` | Текст телеграфа |
| `price` | Цена способности профессии в Market; Hero reward бесплатна |
| `available_to_heroes` | Может ли способность участвовать в послебоевом выборе героев; выключите для служебных способностей Jobs и врагов |
| `allowed_hero_ids` | Герои, которым может быть назначена способность; пустой список означает всех героев |
| `hero_levels` | Ровно четыре полных набора параметров `AbilityLevelDefinition` для Hero-версии |

`priority` не определяет обычный игровой порядок героя. Для врага порядок задаёт `EnemyDefinition.ability_ids`, а для героя используется стабильный порядок экипированных `HeroState.ability_ids`; отдельного управления очередью в Management нет.

### Описание способности

`description` — шаблон, а не готовый текст. Его отображает `ui/common/ability_text.gd` во всех подсказках, на экране выбора способности героя и в карточках столкновений. Числа подставляются из данных способности, поэтому описание не может разойтись с балансом.

| Запись | Что подставляется |
|---|---|
| `{cd}`, `{icd}`, `{area}`, `{search}`, `{cast}`, `{recent}` | cooldown, начальный cooldown, area_radius, target_search_radius, cast_range, required_recent_damage_seconds |
| `{e0.damage}` | поле `damage` эффекта с индексом 0 |
| `{e1.status.default_duration}`, `{e1.status.stat_modifiers.0.value}` | вложенные поля статуса и модификатора |
| `{a*b}` | произведение, например `{e0.value_per_ally*e0.max_allies}` |
| `{x:pct}`, `{x:inv_pct}`, `{x:bonus_pct}`, `{x:abs}` | ×100, (1−x)×100, (x−1)×100, модуль |

У способностей героев с уровнями каждое число показывается по всем уровням: `200/400/600/800`. Текущий уровень выделяется (в подсказке героя — его уровень, на экране награды — уровень после выбора).

Ключевые слова оформляются тегами с цветом и иконкой: `[dmg]` урон, `[heal]` лечение, `[shield]` щит, `[cc]` контроль (оглушение, сон, замедление, провокация), `[buff]` усиление, `[debuff]` ослабление, `[gold]` золото, `[summon]` призыв, `[xp]` опыт, `[kw]` просто выделение. Пример: `Deals [dmg]{e0.damage} damage[/dmg] and [cc]stuns for {e1.status.default_duration}s[/cc].`

Правила оформления: перезарядку, дальность и радиус не пишите в тексте — они уже показаны иконками в шапке. Единица (`%` или `s`) пишется вплотную к токену (`{e0.duration}s`) и становится частью числа. Если уровень известен, показывается одно число; на карточке улучшения — «старое → новое»; без уровня — вся цепочка `200/400/600/800` одним цветом.

Иконки лежат в `res://graphics/ui/ability_icons/`. Строка с типом (ACTIVE/PASSIVE, EMPOWERED ATTACK, уровень) и строка с cooldown, дальностью и радиусом добавляются автоматически — в описании их повторять не нужно.

### Покупаемые и врождённые способности

`innate_ability_ids` профессии есть у каждого её солдата. Покупаемые уровни перечислены в `available_ability_ids` и связаны через `upgrades_ability_id`. В Management все уровни видны заранее: некупленные показаны с замком, пометкой NOT BOUGHT и подсказкой NOT PURCHASED. В магазине есть настоящая иконка, целевая профессия, уровень и пометка UPGRADE для улучшений.

- Militia — врождённая **Strength in Numbers** (`NearbyAllyStatBonusEffect`): +3 брони за каждого другого Militia в радиусе 160, максимум +15.
- Warrior — покупаемый **Bloodthirst I** (`BasicAttackLifestealEffect`): 50% вампиризма от базовых атак. Покупка **Bloodthirst II** добавляет `OnHitStatusEffect` со статусом `status.warrior_sundered_armor` — −5 брони на 6 с за удар, до 10 стаков. Стаки общие для всех Warrior'ов на одной цели.

### Ветеранство на экране

Ранг солдата виден без выбора юнита: шевроны рядом с полосой здоровья в бою, в списке армии и на превью расстановки, крупный знак — на портрете выбранного солдата. Ранги 0–2 — 1–3 бронзовых шеврона (новобранец уже носит один), 3–5 — 1–3 серебряных с планкой, 6–7 — золотые шевроны со звездой. Отрисовка — `ui/common/veterancy_insignia.gd`.

### Выбор цели

| Значение | Поведение |
|---|---|
| `SELF` | Сам владелец |
| `CLOSEST_ENEMY` | Ближайший враг |
| `LOWEST_HP_ALLY` | Повреждённый союзник с наименьшей долей HP |
| `RANDOM_VALID_ENEMY` | Случайный живой враг |
| `NEAREST_NEGATIVE_STATUS_ALLY` | Ближайший союзник хотя бы с одним негативным статусом |
| `RANDOM_ENEMY_WITHOUT_STATUS` | Случайный живой враг без `excluded_target_status_id` |
| `LOWEST_CURRENT_HP_ALLY` | Повреждённый союзник с наименьшим абсолютным текущим HP |
| `MOST_TARGETED_ALLY` | Союзник, которого выбрало целью наибольшее число живых врагов; без таких целей способность не активируется |

`LOWEST_HP_ALLY` и `LOWEST_CURRENT_HP_ALLY` не активируются, если все союзники имеют полное здоровье. `target_search_radius` ограничивает кандидатов до выбора лучшей цели. `RANDOM_ENEMY_WITHOUT_STATUS` не активируется, если указанный статус уже есть на всех живых врагах.

### Доставка

| Значение | Поведение |
|---|---|
| `INSTANT` | Мгновенное применение |
| `MELEE_HIT` | Требует подойти к цели |
| `PROJECTILE` | Создаёт снаряд; при `area_radius > 0` применяет все эффекты к врагам вокруг точки попадания, иначе только к основной цели |
| `AREA_AROUND_TARGET` | Применяет эффекты ко всем подходящим юнитам в радиусе цели |

Для AoE обязательно задайте `area_radius > 0`. Комбинация `SELF + AREA_AROUND_TARGET` создаёт область вокруг владельца и подходит для массового усиления союзников.

### Доступные эффекты

| Тип | Поля | Назначение |
|---|---|---|
| `DamageEffect` | `amount` | Фиксированный сырой урон |
| `HealEffect` | `amount` | Фиксированное лечение |
| `ShieldEffect` | `amount`, `duration` | Временный щит |
| `ApplyStatusEffect` | `status` | Наложение StatusDefinition |
| `StatModifierEffect` | `modifier`, `duration` | Временное изменение характеристики |
| `SummonEffect` | `summoned_unit`, `max_active_summons`, `summoner_contribution_percent` | Призывает рядом с владельцем одного временного юнита и передаёт владельцу настроенную долю contribution |
| `SummonMergeEffect` | `merged_unit`, `stat_multiplier`, `attack_speed_bonus_per_summon`, `duration`, `minimum_summons`, `summoner_contribution_percent` | Временно объединяет всех живых призывов одного владельца, затем восстанавливает их с долей HP объединённого существа |
| `BasicAttackEmpowerEffect` | `lifesteal_percent`, `size_multiplier`, `duration` | Временно даёт вампиризм только базовым атакам и масштабирует модель вместе с collision radius |
| `GoldArmyScalingEffect` | `percent_per_gold` | Усиливает все характеристики армии, кроме movement speed, в зависимости от текущего Gold |
| `ItemStatScalingEffect` | `bonus_percent` | Усиливает только модификаторы экипированных на владельца предметов |
| `TeleportStealthEffect` | `duration` | Телепортирует к самому дальнему врагу и временно запрещает врагам выбирать владельца целью |
| `KillRewardEffect` | `gold_per_kill`, `permanent_damage_per_kill` | Даёт послебоевую награду за личные добивания владельца |
| `RadialEnemyDamageEffect` | `damage`, `radius` | Наносит фиксированный урон врагам вокруг владельца |
| `SmokeBombEffect` | `activation_enemy_radius`, `radius`, `duration`, `dodge_percent` | При наличии врага в радиусе активации создаёт область с шансом полностью избежать входящего урона |
| `MeleeRetaliationEffect` | `radius`, `damage_multiplier` | После ближнего урона по владельцу заставляет остальных союзников в радиусе немедленно ударить атакующего |
| `AttackReflectEffect` | `reflect_percent` | Отражает атакующему долю фактически снятого базовой атакой HP; не срабатывает от способностей и отражённого урона |
| `FocusedDamageEffect` | `damage_per_stack`, `stack_duration` | Добавляет базовым атакам по одной цели неограниченные стаки плоского урона с независимыми таймерами |
| `FrenzyEffect` | `attack_speed_multiplier`, `duration` | Через три секунды после первого урона владельца по врагу ускоряет атаки, перемещает владельца к случайным точкам арены и разрешает атаки ближайших союзников |
| `LeapSlamEffect` | `damage`, `impact_radius`, `knockback_distance`, `stun_duration` | Прыгает к основной цели, наносит ей урон, отбрасывает и оглушает остальных врагов рядом |
| `ThresholdGuardEffect` | `health_threshold`, `shield_max_hp_multiplier`, `armor_multiplier`, `duration`, `cooldown_seconds` | При снижении HP до порога даёт щит от max HP и временный множитель брони |
| `GroundSlamEffect` | `damage_multiplier`, `radius` | Заряжает следующую базовую атаку дополнительным уроном по области вокруг цели |

Каждому эффекту задавайте понятный `effect_id`, например `effect.ice_nova_damage`. Этот ID используется в событиях и статистике, но его уникальность автоматически не проверяется.

Эффекты выполняются по порядку массива. Если цель погибла от первого эффекта, следующие эффекты на неё не применятся. Например, если сначала стоит смертельный damage, следующий burn может не наложиться.

Пассивная способность применяет свои эффекты один раз к владельцу при создании юнита. Её cooldown не используется.

### Уровни Hero abilities

Каждая способность с `available_to_heroes = true` обязана содержать ровно четыре элемента `hero_levels`. Каждый `AbilityLevelDefinition` независимо задаёт:

| Поле | Назначение |
|---|---|
| `cooldown_seconds` | Cooldown этого уровня |
| `area_radius` | AoE radius этого уровня |
| `effects` | Полный список эффектов этого уровня с конкретными amount, duration, status или summon-параметрами |

Level 1 должен воспроизводить базовую Hero-версию способности. Верхнеуровневые `cooldown_seconds`, `area_radius` и `effects` сохраняются для Job и Enemy, если та же способность назначена им отдельно. Combat snapshot героя использует набор из `hero_levels` согласно сохранённому уровню способности.

За каждый полученный Hero Level генератор показывает до двух разных способностей, совместимых только с повысившим уровень героем. Если доступен один вариант, показывается одна карточка; если вариантов нет, этот выбор пропускается. Несколько уровней одного или разных героев образуют последовательную сохраняемую очередь.

Вес новой способности равен `RouteDefinition.new_hero_ability_weight`. Вес улучшения рассчитывается как `hero_ability_upgrade_weight / current_level ^ hero_ability_upgrade_level_penalty`. Поэтому новые способности при стандартных значениях появляются чаще улучшений, а способность Level 3 реже способности Level 1. Параметры находятся в `res://content/demo/routes/demo_route.tres`; по умолчанию веса равны `3`, `1`, а штраф уровня равен `1`.

Новая способность не предлагается герою с четырьмя занятыми слотами. Уже известная способность может предлагаться при полных слотах и повышается на один уровень. Level 4 является максимальным и больше не попадает в пул. Если допустимых вариантов нет вообще, окно награды пропускается.

### Призыв существ

Для призыва используйте active ability с `SELF`, `INSTANT` и одним `SummonEffect`. Настройка распределена так:

| Поле | Что регулирует |
|---|---|
| `SummonEffect.summoned_unit` | Какой `EnemyDefinition` используется как шаблон призыва |
| `SummonEffect.max_active_summons` | Сколько живых существ этого эффекта одновременно может иметь один кастер |
| `SummonEffect.summoner_contribution_percent` | Какой процент от damage, healing и tanking призыва получает владелец для расчёта XP; допустимо `0..100` |
| `AbilityDefinition.cooldown_seconds` | Как часто кастер пытается призвать следующего юнита |

Каждое применение создаёт ровно одного юнита рядом с кастером. Готовая summon-способность имеет высший приоритет между завершёнными ударами: прерывает движение и свободную часть recovery/отступления, но ждёт завершения committed-замаха и его неподвижной анимации. Stun по-прежнему запрещает её применение. При заполненном лимите способность не применяется, не запускает cooldown и не прерывает текущее действие. Погибший призыв сразу освобождает место.

`SummonMergeEffect` также имеет summon-приоритет. На время слияния исходные призывы скрываются и перестают быть живыми целями без генерации death events. Обычный `SummonEffect` этого владельца временно недоступен. При штатном распаде исходные призывы возвращаются с текущей долей HP объединённого существа; при его смерти они погибают. `initial_cooldown_seconds` позволяет запретить слияние в начале боя независимо от обычного recurring cooldown.

Призывы наследуют команду и Veterancy Level кастера. Унаследованный уровень применяет к их собственным базовым характеристикам все шесть настроек `veterancy_*_growth_per_level`. Настроенная через `summoner_contribution_percent` доля damage dealt, effective healing и damage tanked призыва записывается его владельцу и aggregate владельца, поэтому Soldier Summoner получает соответствующую долю veterancy XP и lifetime statistics. При `0` призывы не дают владельцу contribution, при `100` передают её полностью. Оставшаяся доля отбрасывается и не даёт XP самому временному существу. Его damage taken и death остаются видны для диагностики боя. Призывы исчезают после боя, сами не получают progression, не занимают места армии и не считаются permanent death.

Шаблоны слабых призывов находятся в `res://content/demo/summons/summoned_brawler.tres` и `summoned_shooter.tres`. Конфигурации врага, Job и героя независимы:

| Получатель | Ability |
|---|---|
| Enemy Summoner | `ability.enemy_summon` |
| Summoner Job | `ability.summoner_job_summon` через `innate_ability_ids` |

### Как добавить способность

1. В папке нужного владельца дублируйте ближайшую способность, например `heroes/greed/greed_dagger_nova.tres` или `jobs/summoner/summoner_job_summon.tres`.
2. Назначьте новый `ability.*` ID.
3. Выберите `ACTIVE` или `PASSIVE`.
4. Выберите совместимые target и delivery.
5. Создайте или замените вложенные эффекты.
6. Проверьте порядок эффектов.
7. Настройте cooldown и price для базовой Job/Enemy-версии.
8. Для Hero-compatible способности создайте ровно четыре полных `hero_levels`.
9. Подключите способность герою, профессии или врагу по ID.

Способы подключения:

| Получатель | Поле |
|---|---|
| Герой | Послебоевая карточка автоматически назначается конкретному совместимому Hero |
| Профессия | `JobDefinition.available_ability_ids` |
| Врождённая способность профессии | `JobDefinition.innate_ability_ids` |
| Враг или босс | `EnemyDefinition.ability_ids` |
| Конкретный герой через reward | Автоматически для AbilityDefinition с включённым `available_to_heroes` и единственным `allowed_hero_ids` |

Новая способность становится кандидатом награды за Hero Level только при включённом `available_to_heroes`. Выбор создаётся только для конкретного повысившего уровень живого или мёртвого героя, но никогда для казнённого. Для Hero ability укажите ровно один ID владельца в `allowed_hero_ids`; пустые и общие списки в demo не используются.

При покупке Job ability должен быть выбран Soldier нужной профессии или заголовок самой профессии. Active ability заменяет текущий active slot. Passive ability занимает первый свободный passive slot; если все три заняты, предложение нужно перетащить на конкретный заменяемый слот.

## 9. Статусы

Тип ресурса: `StatusDefinition`.

Примеры находятся в `res://content/demo/statuses/`.

| Поле | Назначение |
|---|---|
| `default_duration` | Длительность статуса |
| `max_stacks` | Максимум стаков |
| `stack_policy` | Обновить длительность или добавить стак |
| `periodic_interval` | Интервал периодических эффектов |
| `periodic_effects` | Эффекты каждого тика |
| `stat_modifiers` | Модификаторы на время статуса |
| `prevents_actions` | Полностью запрещает действия |
| `grants_negative_status_immunity` | Пока статус активен, блокирует наложение новых статусов с `polarity = NEGATIVE`; допустимо только для `POSITIVE` |
| `polarity` | `POSITIVE`, `NEGATIVE` или `NEUTRAL`; cleanse снимает только `NEGATIVE` |

`REFRESH_DURATION` обновляет длительность без добавления стака. `ADD_STACKS` обновляет длительность и увеличивает число стаков до `max_stacks`.

Для периодического статуса задайте и `periodic_interval`, и `periodic_effects`. Каждый periodic-эффект выполняется отдельно за каждый стак.

`default_duration = 0` создаёт статус до конца боя. Положительное значение задаёт длительность в секундах. Для `ShieldEffect` и `StatModifierEffect` duration `0` также означает бессрочный эффект.

Чтобы использовать статус в способности, добавьте `ApplyStatusEffect` и назначьте в его поле `status` прямую ссылку на `.tres` статуса.

## 10. Предметы

Тип ресурса: `ItemDefinition`. Все 42 предмета (5 категорий) генерируются скриптом `tools/items/gen_items.py` в `res://content/demo/items/<категория>/`, их способности — в `res://content/demo/abilities/items/`. **Меняйте таблицы в скрипте и запускайте его** (`python tools/items/gen_items.py`): он полностью перезаписывает эти папки и `summons/summoned_skeleton.tres`.

У каждого предмета есть своя PNG-иконка 128×128 в `graphics/ui/item_icons/warcraft/<slug>.png`, в грубом рисованном стиле классических RTS. Способности предмета используют ту же иконку (для двух способностей цепей Despair — одну общую иконку цепей). Чтобы обновить только ссылки на картинки и сохранить текущие балансные правки `.tres`, используйте `python tools/items/gen_items.py --icons-only`.

Исходники и сведения о генерации (FLUX.2 [klein] 9B, seed, task UUID, URL и стоимость) хранятся в `graphics/generated/runware/source/items_wc3/manifest.json`. Команда `python tools/items/download_item_icons.py` восстанавливает 42 картинки из сохранённых URL, повторно используя уже скачанные файлы; новых платных генераций она не запускает. Проверка набора: `res://tests/test_item_icons.gd`.

| Поле | Назначение |
|---|---|
| `category` | `DAMAGE`, `TANK`, `SUPPORT`, `COMMAND`, `UNIQUE` (заголовок тултипа) |
| `passive_effects` | Бонусы характеристик (`StatModifier`) |
| `ability_ids` | Способности предмета (`AbilityDefinition` с `available_to_heroes = false`). Активные герой применяет сам, как свои способности; пассивные включаются в начале боя |
| `allowed_hero_ids` | Уникальный предмет: купить и надеть может только этот герой; на рынке он появляется, только если герой жив |
| `price` / `sell_price` | Цена покупки / продажи (генератор ставит половину цены) |
| `hero_eligibility` | `ANY`, `MELEE` или `RANGED` |

`StatModifier`:

| Поле | Значение |
|---|---|
| `stat` | Основные: `max_hp`, `damage`, `attack_speed`, `movement_speed`, `attack_range`, `armor`. Вторичные: `crit_chance` (%), `crit_multiplier` (x, берётся наибольший, по умолчанию x2), `lifesteal` (% урона базовых атак), `dodge` (% уклонения от базовых атак), `hp_regen` (HP/сек), `cooldown_reduction` (%), `damage_taken` (% получаемого урона, минус = меньше), `armor_penetration` (% брони цели) |
| `operation = ADD` | Прибавить `value` (+45 урона, +25% вампиризма) |
| `operation = ADD_PERCENT` | Процентный бонус: «+25% скорости атаки». Все такие бонусы одной характеристики складываются, затем характеристика умножается один раз: два предмета по +25% = +50% |
| `operation = MULTIPLY` | Умножить на `value` |

Складывание: урон, HP, броня, регенерация, вампиризм и шанс крита — простым сложением (крит не больше 100%). Уклонение и сокращение перезарядки — с убыванием: 35% + 45% = 1 − 0.65 × 0.55 = 64%. Пределы: уклонение 60%, перезарядка 75%.

Механики способностей предметов (эффекты в `content/definitions/effects/items/`, состояние боя — `combat/item_runtime.gd`):

| Эффект | Что делает |
|---|---|
| `OnHitStatusEffect` | Каждая базовая атака накладывает статус (кровотечение Тесака) |
| `OnHitStackTriggerEffect` | Стаки-метки на цели, на N стаках — другой статус, кулдаун на цель (Нить Иглы) |
| `NthHitStatusEffect` | Каждая N-я атака — статус (Петля Лука) |
| `ExecuteOnHitEffect` | Казнь не-боссов ниже порога HP + золото за казнь |
| `LowHealthShieldEffect` | Раз за бой щит + регенерация, пока щит цел |
| `DamageRedirectEffect` | Часть урона по союзникам рядом переходит на героя |
| `EmergencyStealthEffect` | Активная: невидимость и лечение при низком HP |
| `DamageThresholdNovaEffect` | Каждые N полученного урона — взрыв, статус (страх), лечение |
| `AllyRadiusStatusEffect` | Активная: статус всем союзникам в радиусе (0 = вся армия), с условиями |
| `PulseHealEffect` | Каждые N сек лечит ближайших раненых союзников |
| `SoldierDamageAuraEffect` | Аура урона для солдат (ветераны сильнее) |
| `DeathSummonEffect` | Шанс поднять призыв на месте умершего врага (скелеты) |
| `LastRitesEffect` | Активная, раз за бой: неуязвимость и лечение, когда жива меньшая часть армии |
| `IsolationBonusEffect` | Бонусы, пока рядом нет союзников |
| `EnemyCastBuffEffect` | Стак баффа, когда враг рядом применяет активную способность |
| `RageEffect` | Ярость от полученного урона, при пороге — статус |
| `EnemySlowAuraEffect` | Аура замедления атаки и передвижения врагов |
| `KillGrowthEffect` | +Max HP за убийство до конца забега (сохраняется как постоянный модификатор героя) |
| `GoldStatScalingEffect` / `PostBattleGoldEffect` | Бонус от золота игрока / золото после победы |
| `CharmEffect` | Очарование: враг временно сражается за игрока (не боссы) |

Новые флаги статусов: `causes_fear` (юнит убегает от источника и не атакует), `grants_invulnerability` (не получает урон). Новые цели способностей: `HIGHEST_DAMAGE_ENEMY`, `HIGHEST_HP_NON_BOSS_ENEMY`.

Принятые трактовки дизайна: «обездвиживание» = корни (нельзя двигаться, атаковать можно); казнь Перчаток и очарование Вуали не действуют на боссов; радиус взрыва Тернистого Венца 200 (в таблице не указан), Фиал лечит ближайших раненых без ограничения дистанции, Череп реагирует на смерти в радиусе 400; «ветеран» для Знамени — Ветеранство 1+.

Ограничения экипировки: до 6 предметов на героя; один экземпляр нельзя надеть дважды; экипированный предмет нельзя продать. В инвентаре хранятся экземпляры, поэтому два одинаковых предмета складываются.

Чтобы выдать стартовый предмет вручную, добавьте его ID в `DemoRunFactory.create_starting_run()` (`run.inventory.create_item(item_id)`).

## 11. Рынок

Рынок не хранится в отдельном `.tres` и не имеет ручного списка предложений. Предложения генерируются автоматически из предметов, профессий и способностей профессий с учётом текущего состояния забега. Hero abilities в Market не участвуют.

Возможные предложения:

| Тип | Источник |
|---|---|
| Предмет героя | Любой `ItemDefinition`, совместимый хотя бы с одним оставшимся героем |
| Открытие профессии | Любой закрытый `JobDefinition`, кроме `job.militia` |
| Вместимость профессии | Открытая профессия, если вместимость меньше числа солдат |
| Способность профессии | `JobDefinition.available_ability_ids` |

### Что настраивается данными

| Желаемое изменение | Где менять |
|---|---|
| Цена способности | `AbilityDefinition.price` |
| Цена предмета | `ItemDefinition.price` |
| Цена продажи | `ItemDefinition.sell_price` |
| Совместимость предмета | `ItemDefinition.hero_eligibility` |
| Цена открытия профессии | `JobDefinition.unlock_price` |
| Цена вместимости | `JobDefinition.capacity_price` |
| Набор способностей профессии | `JobDefinition.available_ability_ids` |

За один визит рынок создаёт 5-7 предложений. Если доступны обе группы, генератор сначала старается выбрать хотя бы одно предложение для героев и одно для армии. Генерация требует минимум пяти подходящих кандидатов.

Рынок мягко повышает вероятность дорогих предложений для менее развитых героев. Это не гарантия конкретного предмета или способности.

### Что требует изменения кода

| Настройка | Файл и константа |
|---|---|
| Минимум предложений | `market_generator.gd`, `MIN_OFFERS` |
| Максимум предложений | `market_generator.gd`, `MAX_OFFERS` |
| Начальная цена reroll | `market_service.gd`, `BASE_REROLL_PRICE` |
| Рост цены reroll | `market_service.gd`, `REROLL_PRICE_STEP` |

Не добавляйте постоянное предложение напрямую в `MarketState.offers`: это runtime-состояние, оно пересоздаётся при новом визите или reroll и сериализуется в сохранение. Для постоянного присутствия нужен отдельный механизм генерации или гарантированного выбора в `MarketGenerator`.

## 12. Частые ошибки

| Ошибка | Последствие | Решение |
|---|---|---|
| Повторяющийся `id` | Registry отклоняет ресурс | Использовать глобально уникальный ID |
| Переименование старого ID | Ломаются ссылки и сохранения | Не менять ID выпущенного контента |
| Новый герой не появляется | Герой не добавлен в стартовый список | Обновить `DemoRunFactory.HERO_IDS` |
| Новый враг не появляется | Нет ссылки из encounter | Добавить ID в `enemy_ids` |
| Профессия слишком сильная | Использованы defaults нового StatBlock | Дублировать job и обнулить ненужные прибавки |
| Герой с большой range идёт в melee | Нет тега `ranged` | Добавить точный тег `ranged` |
| Способность бесплатна | Не заполнен `price` | Задать цену до проверки рынка |
| AoE не задевает соседей | `area_radius = 0` | Задать ненулевой радиус |
| Лечение применяется не туда | Неверный targeting policy | Использовать `LOWEST_HP_ALLY` или `SELF` |
| Эффект после damage не сработал | Цель умерла от предыдущего эффекта | Изменить порядок эффектов |
| Статус сразу исчезает | `default_duration = 0` | Задать положительную длительность |
| Множитель +20% уменьшает stat | Указано `0.2` вместо `1.2` | Для +20% использовать `1.2` |
| Предмет солдата не появляется | Его job ещё закрыт | Открыть разрешённый job или убрать ограничение |
| Registry прошёл, но ability не работает | Не все ID-ссылки валидируются автоматически | Запустить профильные тесты и реальный бой |

## 14. Граница между контентом и программированием

Можно сделать только ресурсами:

- изменить числовые характеристики;
- создать героя, профессию, врага или босса из существующих механик;
- собрать способность из существующих эффектов;
- создать предмет с существующими модификаторами;
- изменить состав, награду и доступность encounter;
- изменить цены рыночного контента.

Потребуется программирование:

- новая характеристика;
- новый алгоритм выбора цели;
- новый тип эффекта способности;
- масштабирование эффекта от damage или HP;
- новый AI behavior;
- новая логика базовой атаки;
- гарантированные или закреплённые предложения рынка;
- новый тип валюты или правила магазина.

Если требуемое поведение отсутствует в доступных enum или типах эффектов, произвольная новая строка в `.tres` его не создаст.

## 15. События между боями

Тип ресурса: `RunEventDefinition`. Событие случайно определяется после завершения боя и открывается поверх Management после выбора следующего Encounter. Выбранное событие, текущий узел ветки и случайные Soldier targets сохраняются сразу, поэтому загрузка не меняет результат броска. Каждый подтверждённый вариант также сохраняется отдельно.

Пример: `res://content/demo/events/old_shrine.tres`.

### Частота

| Поле | Назначение |
|---|---|
| `RunEventDefinition.weight` | Относительный вес события среди подходящих событий |
| `RunEventDefinition.one_time` | Запрет повторного появления в текущем забеге; по умолчанию включён |
| `RunEventDefinition.theme_hero_id` | Hero, чей authored `placeholder_color` задаёт однотонный фон и рамку окна события |
| `RouteDefinition.event_absence_percent` | Независимая вероятность отсутствия события от `0` до `100` процентов |
| `RouteDefinition.opening_event_id` | Обязательное событие, показываемое поверх поля первого боя до появления армий |
| `RouteDefinition.act_one_post_battle_event_ids` | Обязательные события после боёв Акта I: элемент `0` срабатывает после первого боя, элемент `1` после второго; пустой ID оставляет обычный случайный выбор |

Сначала отдельно проверяется `event_absence_percent`. Если событие должно произойти, конкретное событие выбирается пропорционально `weight` среди подходящих кандидатов. Условия с false, события с нулевым весом и уже выпавшие одноразовые события в выбор не входят.

Сюжетные события маршрута не участвуют в случайном броске и игнорируют `event_absence_percent`. Для них обычно задавайте `weight = 0`, чтобы событие нельзя было получить вне указанной точки маршрута. Стартовое событие проходит через обычные линейные `RunEventNode`; бой начинается только после варианта с пустым `next_node_id`. Обязательное post-battle событие подготавливается и сохраняется после боя, но показывается уже в Management после выбора следующего Encounter.

### Случайные Soldier targets

| Поле | Назначение |
|---|---|
| `soldier_target_count` | Количество разных случайных Soldier, фиксируемых для события |
| `target_allowed_job_ids` | Допустимые Jobs; пустой список разрешает любые |
| `target_min_veterancy_level` | Минимальный Veterancy Level кандидата |

Targets выбираются без повторений через persisted Event RNG. В тексте узла и варианта используйте `{soldier_0}`, `{soldier_1}` и далее. При показе они заменяются сохранёнными именами выбранных солдат. Если подходящих Soldier меньше, чем `soldier_target_count`, событие не участвует в выборе.

### Ветки диалога

`RunEventDefinition.nodes` содержит плоский список `RunEventNode`, а `entry_node_id` задаёт начало. Каждый узел содержит title, body и массив `RunEventChoice`.

| Поле выбора | Назначение |
|---|---|
| `choice_id` | Уникальный ID внутри узла |
| `text` | Текст кнопки |
| `conditions` | Условия доступности |
| `effects` | Эффекты, применяемые одной атомарной транзакцией |
| `next_node_id` | Следующий узел; пустое значение завершает событие |

Если хотя бы один эффект применить нельзя, вариант блокируется целиком. Например, Hero ability нельзя выбрать при четырёх занятых слотах, active Job ability нельзя получить при занятом active slot, а passive Job ability блокируется при трёх занятых passive slots.

### Условия

`RunEventCondition.condition_type` поддерживает:

- `ALWAYS`;
- диапазон Act;
- минимальное Gold;
- наличие доступного Hero;
- открытый Job;
- минимальное число Soldier;
- наличие предмета;
- диапазон Veterancy у сохранённого Soldier target.

Поле `inverted` инвертирует результат. Event-level условия проверяются до случайного выбора события. Choice-level условия повторно проверяются при показе и подтверждении варианта.

### Эффекты

`RunEventEffect.effect_type` поддерживает:

- добавление предмета в общий Inventory без экипировки;
- выдачу и немедленную экипировку Hero ability;
- выдачу и немедленную установку общей Job ability;
- постоянный или временный stat modifier отдельному Hero, случайному Soldier либо всему Job;
- увеличение или уменьшение Hero Level;
- увеличение или уменьшение Veterancy случайных Soldier;
- увеличение или уменьшение Job capacity.

Для Level и Veterancy XP переводится на минимальный порог нового уровня. Значения ограничиваются существующим диапазоном уровней.

Для `STAT_MODIFIER` настройте:

| Поле | Назначение |
|---|---|
| `target_scope` | `HERO`, `SOLDIER_TARGET` или `JOB` |
| `hero_definition_id` / `job_id` | Фиксированная цель для Hero или Job |
| `target_index` | Индекс случайного Soldier target |
| `all_soldier_targets` | Применить ко всем выбранным Soldier |
| `stat` | Одна из шести боевых характеристик |
| `modifier_operation` | `ADD` или `MULTIPLY` |
| `modifier_value` | Положительный бонус либо отрицательный/уменьшающий штраф |
| `battles_remaining` | `-1` для постоянного эффекта или число будущих боёв |

Временный modifier с длительностью `1` действует в следующем бою и удаляется после применения его результата. Preview, restart боя и переходы между экранами длительность не расходуют.
