# CAN BE ONLY ONE HERO
# Последовательный план реализации Steam Demo

Версия плана: 1.0
Движок: Godot 4.7
Язык: GDScript
Целевая платформа: Windows PC / Steam
Графика до этапа полировки: простые цветные заглушки, геометрические формы и текстовые иконки

Принятые решения

- Следующий бой выбирается из 2-3 карточек противников без визуальной карты.
- Demo содержит Act I, первую казнь и 3 боя Act II.
- Количество солдат каждой Job ограничено покупаемой Job capacity.
- Билд казненного героя сохраняется в snapshot и становится недоступен игроку.
- Игра сохраняется только между боями. Активный бой не сериализуется.
- Обязательный объем Demo: Tier A. Расширение контента начинается только после готовности и тестирования Tier A.

Обязательный Tier A

- 3 героя в одном забеге.
- 3 Jobs: Warrior, Archer, Priest/Support.
- 6 обычных типов врагов.
- 1 босс Act I.
- Около 15 способностей героев.
- Около 9 способностей Jobs.
- Около 15 предметов героев.
- Около 4 предметов солдат.
- 6-8 боев Act I, включая обучение и босса.
- Казнь одного героя.
- 3 боя Act II.
- Один экран управления армией.
- Рынок, инвентарь, экипировка, veterancy, resurrection, статистика и Save/Load.

Правила выполнения плана

- Выполнять пункты строго по порядку.
- Не начинать массовое производство контента до прохождения Gate 4.
- Не добавлять новую систему, если она не нужна ближайшему playable milestone.
- Definitions хранят неизменяемые данные. Runtime state хранит изменяемое состояние забега.
- UI не должен быть источником игрового состояния.
- Nodes не должны сохраняться напрямую в save-файл.
- Каждый content object и runtime entity должен иметь стабильный ID.
- Все временные изображения разрешено заменять простыми цветными прямоугольниками и кругами.
- После каждого этапа запускать проект и устранять parser errors, missing resources и warnings, относящиеся к этапу.
