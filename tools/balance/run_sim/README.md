# Balance Lab — симулятор прохождения

Прогоняет **целые забеги** (Акт I, босс, казнь, Акт II) через настоящий код игры: те же сервисы рынка, столкновений, наград, казни и тот же бой. Бой идёт без графики, по 60 шагов на секунду боя, поэтому один бой занимает ~1–2 секунды.

## Запуск

**Окно:** откройте `tools/balance/run_sim/balance_lab.tscn` в редакторе и нажмите **F6** (Run Current Scene). Выберите стили и параметры, нажмите **SIMULATE**. Справа появится сводка, кнопка **OPEN HTML REPORT** открывает полный отчёт.

**Командная строка** (быстрее, удобно для больших прогонов):

```powershell
& "C:\Program Files (x86)\Steam\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe" --headless --path . --script res://tools/balance/run_sim/sim_cli.gd -- styles=all runs=35 heroes=all_trios
```

| Параметр | Значение |
|---|---|
| `styles` | `all` или список: `heroes,one_hero,army,one_job,two_jobs,nothing` |
| `runs` | Забегов на каждый стиль |
| `seed` | Первый сид (забег N любого стиля использует один и тот же сид и тройку героев — стили сравниваются честно) |
| `heroes` | `random` — случайная тройка, `all_trios` — все 35 троек по очереди (лучше для отчёта по героям, `runs=35`), или три id через запятую |
| `jobs` | `random` (по умолчанию) — каждый забег сам выбирает случайные Job A и другую Job B (в забеге N одинаковые для всех стилей); `fixed` — берутся `job_a`, `job_b` |
| `job_a`, `job_b` | Профессии для `jobs=fixed` (по умолчанию `job.warrior`, `job.archer`) |
| `focus_hero` | Индекс героя 0–2 для стиля «Один герой» |
| `pick` | Выбор карты столкновения: `easiest` (по умолчанию), `random`, `hardest` |
| `rerolls` | Сколько раз бот может обновить рынок за визит, если нечего купить |
| `resurrect` | `true`/`false` — воскрешать ли павших героев |
| `out` | Папка отчётов (по умолчанию `user://balance_reports`) |
| `workers` | Сколько процессов Godot считают параллельно: `auto` (по умолчанию, ядра CPU − 1, не больше 12) или число; `1` — всё в одном процессе |

Отчёты сохраняются в `%APPDATA%\Godot\app_userdata\Can Be Only One Hero\balance_reports\`: CSV (строка на забег), JSON (все данные) и HTML.

## Стили (что бот покупает)

| Стиль | Покупки |
|---|---|
| Heroes only | Предметы всем героям: следующий предмет получает самый слабый герой; при 6 предметах самый дешёвый заменяется и продаётся |
| One Hero | Предметы только `focus_hero`; его никогда не казнят |
| Army only | Открытие профессий и вместимость, без лимита на одну профессию (до всего отряда); ополченцы распределяются по свободным местам. Способностей и снаряжения для армии в игре сейчас нет, поэтому бот их не покупает |
| One Job | Всё на одну профессию: при `jobs=random` — случайную в каждом забеге, иначе `job_a` |
| Two Jobs | На `job_a` и `job_b`: место первой получает профессия, у которой мест меньше |
| No upgrades | Ничего не покупает |

Одинаково для всех стилей: события и награды героев за уровень выбираются случайно (сид забега), карта столкновения — по `pick`, павшие герои воскрешаются (если `resurrect`), после босса казнят самого слабого героя (по `MarketGenerator.hero_main_score`).

## Отчёт

- **Play styles** — винрейт, средний номер боя, на котором забег гибнет, потери солдат и героев, куда ушло золото, кривая выживания по боям, таблица «на каком бою умирают».
- **Heroes** — винрейт забегов с героем, среднее число выигранных боёв, средний финальный уровень, урон/танкование/лечение/убийства/смерти за бой и за забег, лучший бой по урону/танку/лечению, как часто героя казнят; график «прогресс по ходу забега» (уровень, урон, танк, лечение, убийства, смертность по номеру боя, переключается кнопками); Акт I против Акта II; матрица «герой × стиль».
- **Encounters** — самые опасные столкновения: процент поражений, потери солдат, длительность, таймауты.
- **All runs** — каждый забег бой за боем (наведите на квадрат) и таблица героев по боям: уровень (прирост), урон / танк / лечение, убийства, гибель.

## Устройство

| Файл | Назначение |
|---|---|
| `run_simulator.gd` | Цикл забега и пошаговый бой (`CombatSession` вручную, фиксированный шаг 1/60) |
| `sim_bot.gd` | Решения бота и стили |
| `sim_batch.gd` | Опции → список конфигураций забегов |
| `sim_report.gd` | Агрегация, CSV/JSON/HTML |
| `report_template.html` | Шаблон HTML-отчёта (данные подставляются вместо `/*__DATA__*/null`) |
| `balance_lab.tscn/.gd` | Окно |
| `sim_cli.gd` | Командная строка |
| `sim_parallel.gd` / `sim_worker.gd` | Параллельный запуск в фоновых процессах |

## Скорость

- Забеги считаются **параллельно** в нескольких фоновых процессах Godot (`sim_parallel.gd` запускает `sim_worker.gd`), по одному на ядро. В окне это поле **Parallel processes**, в командной строке `workers=`. Результат тот же, что и в одном процессе; при STOP сохраняются уже готовые забеги.
- Ускорен сам бой (на ~20–25% и в игре): подсказки к характеристикам больше не собираются при каждом запросе характеристики, ауры не ищутся, если ни у кого в бою их нет, проверки расстояний сначала отсекают далёкие пары.

Бой в симуляторе детерминирован: тот же сид даёт тот же результат. Для этого `Combatant` двигается через `_slide(delta)` (раньше `move_and_slide()`, который вне физического кадра брал длительность кадра) — в игре поведение не изменилось.
